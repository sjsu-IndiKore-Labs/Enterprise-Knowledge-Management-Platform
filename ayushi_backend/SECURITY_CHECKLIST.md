# Security & OWASP Top-10 Verification Checklist (Milestone 6)

**Owner:** Ayushi — Backend & Security Lead  
**Services Covered:** `core-api` (`:8080`) and `audit-service` (`:8081`)

| Security Control / OWASP Category | Implementation in `ayushi_backend/` | Verification Status |
|---|---|---|
| **A01: Broken Access Control (Department Isolation & RBAC)** | `allowedDepartments` is computed strictly server-side from the validated JWT (`ADMIN` → all departments; others → `{user.department, GENERAL}`). Cross-department document/chunk access returns `404 DOCUMENT_NOT_FOUND` (never `403`, preventing existence enumeration) and emits `ACCESS_DENIED`. `MANAGER` writes only own department (`GENERAL` is `ADMIN`-only). `/api/v1/admin/**` requires `ADMIN`. | Verified by automated test suite against all 198 cells of `resources/eval/rbac_matrix.csv` and all `RBAC_DENIED` cases in `resources/eval/golden_qa.jsonl` (`0` leakage). |
| **A02: Cryptographic Failures (Passwords, JWT, S3 KMS)** | User passwords hashed with BCrypt cost 10 (`$2a$10$`). JWTs signed with HS256 using `JWT_SECRET` (≥ 32 bytes) and bounded expiration (`JWT_EXPIRATION_MINUTES=60`). S3 objects encrypted with `SSE-KMS` in AWS and SHA-256 checksums recorded on upload. | Verified in `AuthService`, `S3StorageService`, and `Milestone4And5SecurityAnalyticsTests`. |
| **A03: Injection (SQL & Prompt Injection Pre-Filtering)** | All JPA queries use parameterized specifications/named parameters (`@Param`). Department isolation is pre-filtered before ranking. Prompt-injection queries (e.g., `Q036`) cannot access unauthorized departments because `allowedDepartments` excludes restricted departments before reaching `ai-service`. | Verified in `Milestone4And5SecurityAnalyticsTests`. |
| **A04: Insecure Design (Service Boundary & Internal Token)** | Browser communicates **only** with `core-api`. `ai-service` and `audit-service` are internal-only; `core-api` authenticates to `ai-service` via `X-Internal-Token` and never forwards user JWTs. | Verified in `AiServiceClient`. |
| **A05: Security Misconfiguration (CORS, File Magic Bytes, Limits)** | CORS restricted to `CORS_ALLOWED_ORIGINS`. File upload validates **magic bytes** (`%PDF-` for PDF, `PK\x03\x04` for DOCX) and rejects spoofed extensions (`415`) or files > 25 MB (`413`). Containers run as non-root user `ekm`. | Verified in `CorsConfig`, `DocumentService`, and `Milestone1To3BackendTests`. |
| **A07: Identification & Authentication Failures** | Inactive users (`active = false`) and invalid credentials receive a generic `401 UNAUTHENTICATED` response (`Invalid email or password`) to prevent account enumeration, while `LOGIN_FAILED` is recorded in `audit_logs`. Chat endpoints enforce per-user rate limiting (20 req/min → `429`). | Verified in `AuthService` and `ChatRateLimiter`. |
| **A09: Security Logging & Monitoring Failures** | Every request is assigned an `X-Request-Id` (`traceId`) in SLF4J MDC and formatted as structured JSON (`logback-spring.xml`). JWTs, passwords, and API keys are never logged. Every security-relevant action emits an `AUDIT_EVENT` to SQS `ekm-audit-events` consumed idempotently by `audit-service`. | Verified in `RequestIdFilter`, `AuditEventPublisher`, and `AuditEventConsumerServiceTest`. |
